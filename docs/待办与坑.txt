== 坑：PyInstaller 打包 ==
- build.bat 若用命令行参数打包，每次会重新生成 spec，
  手改 spec 无效；要改 spec 就让 build.bat 直接用 spec 打包
- 打包入口文件（launcher.py）必须单独测试：
  python launcher.py 能弹出界面，才能打包
  （gui.py 能跑 ≠ launcher 能跑）
- gui.run_gui() 必须写在 try/except 外面，
  放进 except 里会导致 import 成功就静默退出、无界面无报错
- build.bat 要检查 errorlevel，否则打包失败也喊"打包完成"
- 调试期 spec 里 console=True，能看报错；正式发布改回 False
- launcher 已带崩溃日志兜底：exe 启动失败看旁边的 崩溃日志.txt

== 坑：编码 ==
- cmd 用 echo/重定向写中文 txt，默认 GBK 且无标签，
  UTF-8 默认的编辑器打开就乱码；写中文文件先 chcp 65001
  或直接在 VS Code 里写
- 文件被错误编码打开后"保存"，内容会被替换符永久破坏，
  不可恢复（本文件旧版就是这么没的）
- bat 里有 chcp 65001 → 必须存 UTF-8；没有 → 必须存 ANSI

== 坑：NameError 类报错先查 import ==

== 坑：VS Code 解释器与实际运行环境不一致 ==
- 现象：Pylance 全线报 Import could not be resolved（黄警告），
  但命令行运行一切正常
- 根因：命令行用 Python314（库都装在这），VS Code 选的是别的解释器
- 规约：报 import 警告先对账——命令行 python -c "import sys;
  print(sys.executable)" 的路径 vs VS Code 右下角解释器，不一致先切换
- 提醒：黄色警告≠红色错误，程序能不能跑以命令行实际运行为准

== 坑：子窗口 import 原生 ttk 却用了 bootstyle ==

  看控制台最后一行 TclError 落在哪个控件上
